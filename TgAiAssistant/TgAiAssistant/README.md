# TgAiAssistant — XBoard Telegram AI 助手

版本：1.2.6 · 作者：www.xhj.me · 协议：[MIT](LICENSE)

复用 XBoard 主 Telegram 机器人，提供 AI 问答、知识库、群聊记忆、违规审核、编辑消息监听和管理员通知。

## 安装与升级

1. 配置 XBoard 主 Bot Token 和 Webhook，启用 `telegram` 插件。
2. 将 `TgAiAssistant` 目录打包 ZIP，在后台插件页上传、安装并启用。
3. 配置公共 API 地址、Key、默认模型。接口需兼容 `/chat/completions`，返回 `choices[0].message.content`。
4. 按需要开启问答、记忆与审核。所有配置通过插件配置页维护。
5. 确保消费 `default`（问答）和 `send_telegram`（审核与通知）队列。

安装自动执行迁移，必要时手动运行：

```bash
php artisan migrate --path=plugins/TgAiAssistant/database/migrations
```

升级后重启常驻进程。以下容器名仅为示例：

```bash
docker restart xboard-web-1 xboard-horizon-1
```

宿主项目当前要求 PHP 8.2+ / Laravel 12，并需支持 mbstring。Redis `retry_after` 应大于 120 秒，任务应允许运行 120 秒。

## 配置分区

后台采用平铺表单，通过标签前缀分区；完整字段及默认值见 `config.json`。

| 模块 | 配置内容 |
|---|---|
| 公共配置 | API 地址、Key、默认模型、通知接收 Telegram ID |
| AI 问答 | 开关、私聊/群触发、绑定限制、提示词、历史、输出额度、限流、等待提示 |
| 知识库 | RAG 开关、自定义 JSON、检索片段数量 |
| 群聊记忆 | 采集开关、群范围、自动入库、最短字数 |
| 违规审核 | 审核与编辑监听开关、群范围、独立模型、规则、门槛、禁言时长、通知及 Debug |

审核模型留空时复用公共模型。问答开关与问答限流不控制审核。`llm_models` 是预留字段，当前没有 `/model` 切换。

## 问答

```text
/ask 如何绑定账号？
/ask@你的机器人用户名 我的流量还有多少？
@你的机器人用户名 你好
```

群聊需开启 `enable_group`；私聊普通文本需开启 `enable_free_text`。开启 `require_bind` 后需先私聊机器人发送 `/bind 自己的订阅链接`，勿把订阅链接公开到群。
回答、等待及错误提示引用原问题；长回答分段引用。原消息删除时允许不带引用发送。

私聊按用户 chat_id 独立保存历史，群聊按群 chat_id 共享，默认最近 5 轮、10 条问答。普通聊天不全部写入对话历史。
已绑定用户的问答可能加入邮箱、套餐、流量及到期时间；群内共享历史可能让其他成员的后续请求看到回答里的账户信息，敏感查询建议私聊。
限流按 chat_id 共用，默认每分钟 10 次。并发任务不保证回复顺序和上下文串行一致性。`max_tokens` 限制输出，不限制总输入。

## 知识库与记忆

```json
[
  {"title": "如何绑定", "content": "私聊机器人发送 /bind 自己的订阅链接"}
]
```

RAG 为文本包含检索，不是向量检索。默认最多 3 条片段，每条最多 800 字符。
群记忆默认关闭，开启后采集符合长度要求的非命令群文本：默认至少 10 字，最多保存 2000 字。
自动入库写入 `v2_tg_ai_knowledge` 并按内容去重；关闭自动入库则写入 `v2_tg_ai_group_memory` 的 pending 记录，当前没有审核导入页面。
对话存于 `v2_tg_ai_conversations`，每条最多 4000 字符。上述记录没有自动清理功能。
群采集范围 `[]` 表示所有群，也可填写 `[-1001234567890]`。入库知识没有按群隔离，可能被其他群或私聊检索。
编辑后的消息不会自动更新或清理已入库的旧内容。系统知识的订阅受限内容过滤尚需完善，不应依赖当前过滤保障内容保密。

## 群聊审核和编辑监听

主机器人必须是超级群管理员，具有删除消息、限制成员权限。开启 `enable_moderation`，群 ID `[]` 表示所有超级群。
普通群、群主、管理员、机器人和匿名发送身份不进入当前审核，不需要 @ 机器人。
默认关注色情推广、赌博、毒品交易/制贩指导、危险爆炸物内容；广告引流需自行补充规则。
每条文本单独调用 AI，仅携带文本与审核规则，不携带聊天历史或账户信息。当前没有本地预筛、批量审核或重复内容分类缓存。
明确违规且自评分达到门槛时分别删除、禁言，并在群内报告实际结果；默认禁言 60 分钟。
AI 或前置检查异常不处罚。置信度是模型自评而非校准概率，当前示例可能导致频繁输出 0.99；不能将门槛视为准确率保证。
误判时群管理员可手动解除禁言。

`moderation_watch_edits` 默认开启，原 Webhook 接收 `edited_message` 并验证原访问令牌。同消息文本变更后重新审核，同内容重复推送在 48 小时内去重。
编辑不会重复问答或入库。Webhook 若设置事件白名单，需包含 `edited_message`。
当前不审核图片、视频、语音、媒体说明或链接目标。

## 私聊通知与 Debug

`admin_telegram_ids` 填个人数字 ID 数组，如 `[123456789, 987654321]`；不能填群 ID 或机器人用户名。
`[]` 时通知所有已绑定 Telegram 的 XBoard 管理员，不包含仅有客服身份的账号；与支付通知规则不同。
接收人先私聊主机器人发送 `/start`；依赖默认接收时还需绑定管理员账号。

- `moderation_notify_admin` 默认开启：发送违规原文、类别及处罚结果。
- `moderation_debug` 默认关闭：开启后发送每次 AI 审核和前置检查失败报告，正常消息也通知。
- 管理员免审、范围外、相同内容重复事件不报告。Debug 开启时违规合并为一份报告。
- 通知独立排队并重试，长原文截断到 1800 字符；发送失败不撤销处罚。

## 排查与验证

| 问题 | 检查 |
|---|---|
| 思考中无回答 | default 队列、接口、模型与返回格式 |
| AI 内容为空 | choices[0].message.content、模型输出额度 |
| 无审核/Debug | 审核和 Debug 开关、超级群、普通成员测试、send_telegram 队列、常驻进程重启 |
| CHAT_ADMIN_REQUIRED | 主 Token 对应机器人在当前群的实际管理员权限 |
| 通知失败 | 个人 ID、已 /start、未屏蔽机器人、Telegram 具体错误日志 |
| 编辑不审核 | 编辑开关和 Webhook 事件列表 |

日志位于宿主 `storage/logs`。反馈时遮掉 Token、Key、订阅链接及个人数据。
`tests/*_smoke.php` 可在 PHP 环境独立运行，用于部分逻辑回归，不替代真实 Telegram / AI / 队列验证。
